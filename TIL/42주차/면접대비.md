## std::move가 무엇인지 설명해 주세요. 그리고 std::move(a)를 호출했다고 해서 반드시 실제 이동이 발생하는 것은 아닌 이유도 함께 설명해 주세요.

std::move는 객체를 실제로 이동시키는 함수가 아니라, 해당 객체를 이동 가능한 값(xvalue)으로 캐스팅하는 함수

### 심화

```c++
std::string a = "hello";
std::string b = std::move(a);
```

실제 자원 이동은 std::move(a)가 아니라, 그 결과를 받은 std::string의 move constructor가 수행

## 프로세스와 스레드의 차이를 설명해 주세요. 그리고 게임에서 여러 작업을 동시에 처리할 때 프로세스를 여러 개 만드는 대신 스레드를 사용하는 이유는 무엇인가요?

프로세스는 독립된 메모리 공간을 가진 실행 단위, 스레드는 프로세스 내부에서 실제 작업을 수행하는 실행 단위, 같은 프로세스의 스레드들은 메모리를 공유하기 때문에 데이터 공유가 쉽고, 프로세스보다 생성과 컨텍스트 스위칭 비용이 작아 여러 작업을 병렬 또는 동시 처리할때 주로 사용

## Race Condition을 막기 위해 Mutex를 사용할 수 있습니다. Mutex가 무엇인지 설명하고, Mutex를 너무 많이 사용하면 어떤 문제가 생길 수 있는지 설명해 주세요.

Mutex는 공유 자원이나 임계영역에 동시에 여러 스레드가 들어가지 못하도록 상호 배제하는 동기화 도구입니다. 너무 많이 사용하면 락 경합때문에 대기시간이 늘고, 컨텍스트 스위칭 비용이 커질 수 있습니다. 또, 여러 Mutex를 서로 다른 순서로 잡으면 Deadlock 위험도 생깁니다.

## Mutex와 Semaphore의 차이를 설명해 주세요. 게임에서는 각각 어떤 상황에 사용할 수 있을까요?

Mutex는 임계영역에 한 스레드만 접근하도록 하고, Semaphore는 동시에 접근 가능한 스레드 수를 일정 개수로 제한합니다. Mutex는 골드 값을 여러 스레드가 동시에 수정하지 못하도록 보호하는 경우, Semaphore는 텍스처나 사운드 에셋을 비동기로 읽는 작업이 100개 생겼어도 부하때문에 4개까지 한번에 로드하도록 세마포어를 걸수도 있다.

## Deadlock이 무엇인지 설명하고, Mutex A와 Mutex B가 있을 때 어떤 상황에서 Deadlock이 발생할 수 있는지 예를 들어주세요.

Deadlock은 여러 스레드가 서로가 보유한 자원을 기다리면서 영원히 진행하지 못하는 상태, 서로 다른 순서로 락을 잡으면서 순환대기가 생김

## 내부 파편화와 외부 파편화의 차이점

외부 파편화는 메모리 사이사이에 작은 빈공간이 흩어지는것
내부 파편화는 실제 필요한것보다 큰 메모리 블록을 할당받아서 할당된 블록 내부가 낭비되는것

```
10바이트 필요
↓
Allocator가 16바이트 블록 할당

[ 실제 사용 10 ][ 낭비 6 ]
```
