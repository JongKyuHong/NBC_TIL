# CS

## 복습

### 프로세스와 스레드의 차이를 메모리 공유 관점에서 설명

스레드는 코드/힙/전역 데이터는 공유하고, 각자 스택/레지스터는 별도라는 점 추가하기, 컨텍스트 스위칭은 아른 프로세스에 있는 스레드로 전환될때 프로세스 간 컨텍스트 스위칭도 발생한다.

컨텍스트 스위칭이 발생하면 운영체제가 TCB(스레드 제어 블록) 같은 자료구조에 레지스터 값, 현재 실행중이던 명령어 위치(프로그램 카운터), 스택 포인터 같은 스레드 상태를 변경하는데 다른 프로세스에 있는 스레드로 스위칭되면 여기에 주소공간(페이지 테이블)도 바꿔야 해서 비용이 더 크다. TLB도 변경해야됨

### 페이지 테이블

가상 주소를 실제 RAM주소로 바꿔주는 테이블이다. 보통 프로세스 하나당 하나씩 있음

### TLB

Translation Lookaside buffer, 주소 변환 캐시, 페이지 테이블을 매 메모리 접근마다 찾아보면 느리므로 최근에 사용한 가상주소 -> 물리 주소로 변환한 결과를 TLB에 저장해둠
CPU의 MMU(Memory Management Unit)에서 다단계 페이지 테이블을 따라 주소를 변환하고 그 변환 결과를 TLB에 캐싱

### 데이터 레이스와 레이스 컨디션 차이

데이터 레이스 : 여러 스레드가 하나의 자원에 접근하고 그 중 하나가 쓰기작업인데 동기화가 없는 경우, mutex나 atomic같은 동기화로 해결 가능
레이스 컨디션 : 스레드의 실행 순서가 달라지면 결과에 차이가 생겨 로직이 잘못되는 문제, 공유 데이터를 확인하고 수정하는 구간을 뮤텍스로 잠가 한 스레드씩만 처리하도록 방지

### 포인터와 레퍼런스의 차이 3가지

- 포인터는 nullptr로 초기화 가능 레퍼런스는 초기화시 무조건 값을 넣어야함
- 포인터는 주소를 저장하는 변수고 레퍼런스는 별칭
- 포인터는 재할당이 가능하고 레퍼런스는 안된다.

### 데드락이란 무엇이고 어떻게 예방하는가?

데드락은 두개의 스레드가 서로 작업하고 있는 자원에 접근하려고 무한하게 대기하고 있는 상황, 모든곳에서 락을 잡는 순서를 똑같이 정하는것이 대표적인 예방법

### Actor의 생명주기

생성자 -> Onstruction -> BeginPlay -> Tick -> Endplay -> GC

### 가상함수란 무엇이고 부모클래스의 소멸자를 virtual로 선언해야 하는 이유는 무엇인가?

가상함수란 부모의 포인터나 레퍼런스로 호출해도 실제 객체가 자식이면 자식의 오버라이딩 함수가 호출되게 하는함수, 부모 소멸자에 virtual이 없으면 부모의 소멸자만 호출되고 자식의 소멸자는 호출되지 않은상태로 메모리에 남는다.

### 불편하지만 수동으로 메모리 관리를 하는 이유는 뭘까?

C++은 객체가 생성되고 파괴되는것을 직접 제어할 수 있음, 게임은 예측 불가능한 GC멈춤을 피해야 하므로 필요한 시점에 자원을 확실히 해제하고 메모리 풀같은 최적화를 적용하기 위해 수동 관리 또는 RAII기반 관리를 사용한다.

### 임계영역(크리티컬 섹션)이란?

공유 자원에 접근하거나 수정하는 코드 구간, 예시로 `gold-=100`처럼 여러 스레드가 동시에 실행하면 문제가 생기는 코드가 임계영역이고 뮤텍스로 잠궈서 한번에 한 스레드만 들어가게 한다.
