## 파츠 장착/해제 안되는 문제

아웃런 파츠NPC에서 장착/해제가 안됨

PlayerController에 있는 EquipPartLive가 안불러지던 문제를 고쳤음 EquipPartLive를 불러서 실제로 장착이 되게끔함
if문 분기를 IsPartOwned(SelectedRow.Definition)으로 파츠 장착된것을 확인해서 이것도 분기
EquipComponent에서 ClearAll할때 슬롯비워짐을 위해서 슬롯별로 알림 보냄(파츠 체인지)

# 인런 파츠 업그레이드 NPC (M3_IRU_1) 설계

## 1. 개요

인 런 중 파츠 NPC 상호작용 시 표시되는 UI. 임시 재화로 파츠 수치 리롤 / 등급 업그레이드를 수행하는 인터페이스를 구현하여, 런 중 빌드 강화 선택을 지원한다.

## 2. 채택한 가정

1. 비용/확률 데이터는 전용 DataTable (`DT_PartUpgrade`) — DataTable 우선 원칙
2. 등급업 실패해도 재화 소모 (일반적인 로그라이트 도박 구조)
3. RollCount 리셋 없음 — 파츠 교체 시 `FNSPartData`가 새로 만들어지며 자연 리셋
4. 등급업 성공 확률은 등급별 차등 (커먼→레어 높게, 에픽→레전더리 낮게)

## 3. 핵심 판단

리롤/등급업 서버 로직(`Server_RequestReroll`, `Server_RequestUpgradeRarity`, `RollCount`)은 이미 `UNSPartEquipComponent`에 구현돼 있다. 이번 작업의 본질은 다음 세 가지다.

1. 재화 게이트 추가
2. 실패 피드백 경로 추가
3. NPC + 위젯 신설

## 4. 데이터 계층 — `FNSPartUpgradeRow` (신규, NSPartTypes.h에 추가)

`DT_PartUpgrade`에 등급별 1 row (Common/Rare/Epic/Legendary):

| 필드                   | 의미                                                         |
| ---------------------- | ------------------------------------------------------------ |
| `Rarity`               | 이 row가 적용되는 현재 등급                                  |
| `RerollBaseCost`       | 해당 등급 리롤 기본 비용                                     |
| `RerollCostIncrement`  | 리롤 1회당 비용 증가치 → 비용 = Base + Increment × RollCount |
| `UpgradeCost`          | 다음 등급으로 업그레이드 비용                                |
| `UpgradeSuccessChance` | 등급업 성공 확률 (0~1)                                       |

Legendary row는 리롤 비용만 사용(등급업 필드 무시). 기존 `UpgradeSuccessChance` UPROPERTY는 DT로 대체(제거). DT 접근은 기존 `NSPartUtils::ResolvePartRow`와 같은 방식의 헬퍼를 추가한다.

## 5. 서버 로직 — `UNSPartEquipComponent` 확장 (기존 RPC 재사용)

### 비용 조회 (BlueprintPure, 클라에서도 호출 가능)

`GetRerollCost(Slot)`, `GetUpgradeCost(Slot)`, `GetUpgradeChance(Slot)` — 복제된 `EquippedParts`(RollCount, CurrentRarity 포함)와 DT 에셋만으로 계산되므로 클라 UI가 RPC 없이 비용/확률을 표시할 수 있다.

### `RerollStat` 수정

기존 검증(bCanReroll 등) 통과 후, PlayerState의 `UNSCurrencyComponent::TrySpendTemp(리롤비용)` 실패 시 리턴. 성공 시 기존 로직 그대로 (RollCount++ → 다음 리롤 자동 인상).

### `UpgradeRarity` 수정

Legendary 체크 후 `TrySpendTemp(업그레이드비용)` — 소모 먼저, 그다음 DT 확률로 판정(실패해도 재화는 이미 소모).

### 결과 피드백 (신규)

현재 실패 시 클라가 아무것도 모르는 문제 해결.

```cpp
enum class ENSPartUpgradeResult : uint8 { RerollDone, UpgradeSuccess, UpgradeFail, NotEnoughCurrency };

UFUNCTION(Client, Reliable)
void Client_NotifyUpgradeResult(FGameplayTag Slot, ENSPartUpgradeResult Result);

DECLARE_MULTICAST_DELEGATE_TwoParams(FNSOnUpgradeResult, FGameplayTag, ENSPartUpgradeResult);
FNSOnUpgradeResult OnUpgradeResult; // 위젯이 구독
```

수치 갱신 자체는 기존 `OnRep_EquippedParts → OnPartChanged` 경로가 이미 처리하므로, 이 RPC는 연출(성공/실패 이펙트, 재화 부족 알림) 전용이다.

## 6. NPC — `ANSPartUpgradeNPC` (신규, `Interaction/NPC/`)

`ANSPartsNPC`와 동일한 미니멀 패턴: `ANSInteractableNPCBase` 상속, `TSubclassOf<UNSPartUpgradeWidget>` 프로퍼티 + `GetInteractionWidgetClass()` 오버라이드. 인런 전용이므로 아웃런 NPC의 해금(SaveGame) 로직은 없다. `ShouldHandleOnServer`는 기본 false — UI 열기는 로컬, 실제 소모/변경은 위 Server RPC가 재검증.

## 7. UI — `UNSPartUpgradeWidget` (신규, `UI/Interaction/`)

`UNSNPCInteractionWidgetBase` 상속, `NSPartEquipWidget`의 열기/닫기·입력모드 패턴을 따른다.

- **구독**: `OpenForInteractor`에서 PlayerState의 EquipComp/CurrencyComp를 얻어 `OnPartChanged`(수치 갱신), `OnTempChanged`(잔액 갱신), `OnUpgradeResult`(연출) 바인딩. `CloseWidget`에서 해제.
- **슬롯 카드 3개 (Body/Arm/Leg)**: 부위, 등급(색상), 효과 수치 표시. 등급 색상은 기존 파츠 UI(NSPartDetailWidget 계열)의 등급 색상 처리를 재사용.
- **리롤 버튼**: 비용 표시(`GetRerollCost`). 비활성 조건: 미장착, `bCanReroll == false`(레그), 잔액 부족.
- **등급업 버튼**: 비용 + 성공확률 표시. 비활성 조건: 미장착, Legendary, 잔액 부족.
- **잔액 표시**: `GetTemp()` + `OnTempChanged`로 실시간 갱신.
- **연출**: `OnUpgradeResult` 수신 → `BlueprintImplementableEvent`(성공 이펙트/실패 셰이크/재화부족 토스트)로 BP에 위임.

## 8. 멀티플레이 안전성

- 비용 검증·차감·확률 판정은 전부 서버(`TrySpendTemp`는 서버 전용 API). 클라 버튼 비활성화는 UX일 뿐, 서버가 항상 재검증.
- 잔액·파츠 상태 모두 이미 복제 중(FastArray 지갑, `EquippedParts`)이라 추가 복제 불필요.
- Seamless Travel은 기존 `CopyRunStateFrom`이 RollCount 포함 `FNSPartData`를 통째로 이관하므로 리롤 비용도 자동 이월.

## 10. 구현 순서

1. `FNSPartUpgradeRow` + DT 조회 헬퍼 → 검증: 컴파일(사용자 빌드)
2. `RerollStat`/`UpgradeRarity`에 재화 게이트 + `Client_NotifyUpgradeResult` → 검증: PIE에서 재화 부족/성공/실패 로그
3. `ANSPartUpgradeNPC` + `UNSPartUpgradeWidget` C++ 골격
4. 에디터 작업(사용자): `DT_PartUpgrade` 생성·수치 입력, WBP 제작, NPC BP 배치
