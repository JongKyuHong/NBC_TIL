## 1. 파츠 데이터 구조 정의

### `Source/NeoSanctum/Data/Part/NSPartTypes.h`

파츠 관련 핵심 구조체가 모여있는 파일. 세 단계로 진화함.

1. **최초**: `FNSPartDefinitionRow`(DataTable row 구조체) 신설 — `Definition`(DA 소프트 참조), `PartSlot`, `bCanReroll`, `UnlockCost`, `ValueRange`, `bEnabled`. 파츠 수치를 DA가 아니라 DT에 두기로 한 결정의 시작점.
2. **`FNSPartSlotRow` 추가 + `ENSPartSlot` enum 폐기 → `FGameplayTag PartSlot`**: 슬롯을 고정 enum(Body/Arm/Leg 3개)이 아니라 GameplayTag로 바꿔서, 슬롯 자체도 DT(`FNSPartSlotRow`: `SlotTag`, `UnlockCost`, `bUnlockedByDefault`, `bEnabled`)로 데이터화. 슬롯 언락 개념(비용, 기본 해금 여부)이 이때 처음 생김. `FNSPartData::Slot`도 enum → tag로 변경.

### `Source/NeoSanctum/Data/Part/NSPartDefinition.h`

DA(DataAsset) 쪽에 있던 `PartSlot`/`bCanReroll`/`ValueRange`를 삭제. 위 DT 구조체로 옮기면서, DA는 `PartName`/`EffectClass`/`PartMesh`/`Icon` 같은 "정체성·에셋 참조"만 남기고 수치는 전부 DT로 위임. (계기: "수치는 DataTable, DataAsset은 구조/참조만"이라는 프로젝트 규칙)

## 2. 데이터 로드 파이프라인 — `NSDataSubsystem`

### `Source/NeoSanctum/Core/GameInstance/Subsystem/NSDataSubsystem.h/.cpp`

세 단계로 발전:

1. `BuildPartRowCache()` 신설 — DT를 읽어 `TMap<FPrimaryAssetId, FNSPartDefinitionRow> CachedPartRowsByDefId`에 캐싱, `GetPartRow()`/`GetAllPartRows()`로 조회 제공. `OnOutGameReferenceAssetsLoaded()`에서 호출.
2. DT 에셋 참조를 처음엔 `NSDataSubsystem` 안에 직접(`TObjectPtr<UDataTable> PartDefinitionTable`) 뒀다가, 곧바로 `UNSDataSettings`(신설한 `UDeveloperSettings`)로 이관 — `OnOutGamePrimaryAssetsLoaded()`를 새로 만들어 Settings의 소프트 참조를 비동기 로드 후 캐시 빌드.
3. **최종적으로 `UNSDataSettings` 자체를 폐기**하고 `NSCommonDataConfig`(기존에 있던 공용 데이터 설정 DA)로 재이관. 이유: 다른 모든 데이터가 "페이즈 전용 PrimaryDataAsset + AssetBundle" 패턴을 쓰는데 파츠만 `UDeveloperSettings`(프로젝트 세팅, 페이즈 개념 없음)를 써서 구조가 어긋나 있었음. `OnCommonAssetsLoaded()`에서 `BuildPartRowCache()`/`BuildSlotRowCache()`(슬롯 DT용으로 같이 신설) 호출하도록 정리. `GetSlotRow()`/`GetAllSlotRows()`도 이때 추가.

### `Source/NeoSanctum/Data/Config/NSCommonDataConfig.h`

`PartsBaseStatTable`, `PartsSlotBaseStatTable` 필드 추가 (`AssetBundles="CommonData"`) — 파츠 DT 2개를 여기로 옮겨받는 자리.

### `Source/NeoSanctum/Data/Util/NSDataSettings.h/.cpp` (삭제)

잠깐 만들었다가 위 이유로 완전히 삭제. `Config/DefaultGame.ini`의 관련 섹션도 같이 제거.

### `Source/NeoSanctum/NeoSanctum.Build.cs`

`NSDataSettings`(`UDeveloperSettings` 상속) 만들 때 `"DeveloperSettings"` 모듈 의존성 추가. (참고: `NSDataSettings` 자체는 나중에 삭제됐지만 이 모듈 의존성 라인은 diff상 그대로 남아있음 — 다른 데서 안 쓰면 정리 대상)

## 3. 파츠 조회 유틸 — `NSPartUtils`

### `Source/NeoSanctum/Progression/Part/NSPartUtils.h/.cpp`

- `ResolvePartRow(WorldContextObject, DefId)` 신설 — `NSDataSubsystem::GetPartRow()`를 경유하는 조회 헬퍼. `PurchasePart`/`EquipPart`/`RerollStat`/`RollValueForRarity` 등 여러 곳에서 DA를 직접 로드하는 대신 이걸 거치게 됨.
- 후속으로 `ResolvePartDefinition(WorldContextObject, TSoftObjectPtr<UNSPartDefinition>)` 오버로드 추가 — 기존엔 `FNSPartData`를 받는 버전만 있었는데, 카탈로그 선택(`FNSPartDefinitionRow::Definition`)과 장착중 조회(`FNSPartSaveData::Definition`) 양쪽에서 "소프트포인터 → 캐시 경유 Definition"이 필요해져서 공용화. 기존 `FNSPartData` 버전은 이 오버로드에 위임하도록 리팩터.

## 4. 서버 진행 로직 — `NSProgressionSubsystem`

### `Source/NeoSanctum/Core/GameInstance/Subsystem/NSProgressionSubsystem.h/.cpp`

파츠 구매/장착/슬롯 언락의 실질적인 백엔드. 여러 단계로 완성됨:

- `PurchasePart(Definition, Rarity)` — 처음엔 `Cost`를 파라미터로 직접 받았으나, DT에서 `Row->UnlockCost`를 읽어오는 구조로 변경(`LoadSynchronous` 제거가 핵심 동기). 최종 버전엔 슬롯 언락 여부 체크(`IsSlotUnlocked`)도 추가되어, 슬롯이 안 열려있으면 구매 자체가 실패하도록 함.
- `SetEquippedPart(CharacterId, Definition, Rarity)` / `GetEquippedPart(CharacterId)` — 장착 저장/조회. `Definition`이 null이면 해제로 처리(장착 해제 기능이 이 널 체크 하나로 동작).
- `IsPartOwned`, `GetCommonCurrency`, `GetLastSelectedCharacterId` — 조회용.
- `UnlockSlot(CharacterId, Slot)` / `IsSlotUnlocked` / `GetSlotUnlockCost` — 슬롯 언락 로직. 재화 체크 실패, Row 없음, 이미 해금됨 등 각 실패 분기에 진단 로그 추가(원래 로그가 하나도 없어서 재화 부족 때문에 언락이 안 되는 걸 못 찾고 있었음).

### `Source/NeoSanctum/Progression/Save/NSPermanentSaveGame.h`

- `FNSCharacterSaveData::UnlockedSlots`(`TSet<FGameplayTag>`) 추가 — 슬롯 언락 상태 저장.
- `OwnedParts`(계정 공유 파츠 인벤토리) 필드 위치 정리.

### `Source/NeoSanctum/Progression/Part/NSPartEquipComponent.h/.cpp`

실제로 GAS 이펙트를 붙이고 캐릭터에 파츠를 장착하는 컴포넌트.

- `EquipPart`/`RerollStat`/`RollValueForRarity`가 `Def->PartSlot`/`Def->ValueRange`를 직접 읽던 걸, DT 이관 이후 `NSPartUtils::ResolvePartRow()`로 대체.
- 슬롯 타입을 `ENSPartSlot` enum에서 `FGameplayTag`로 전면 전환 (delegate 시그니처 `FNSOnPartChanged`, `HasEquippedPart`, `GetEquippedPart`, `FindPart`, `DropPartInSlot`, `RemovePartEffects`, `RemoveGEForSlot`, `RemoveAbilitiesForSlot`, `ApplyPartEffect`, `Internal_ApplyGE`, `OnEffectLoaded`, `GrantAbilities`, `OnAbilitiesLoaded`, `RerollStat`, `UpgradeRarity`, 관련 `TMap` 전부 포함).

### `Source/NeoSanctum/Character/Component/NSPartVisualComponent.h/.cpp`

캐릭터 몸에 파츠 메시를 실제로 붙이는 컴포넌트(리더포즈 방식). 위와 같은 이유로 슬롯을 enum → tag로 전환. 이 과정에서 하드코딩되어 있던 `{ ENSPartSlot::Body, ENSPartSlot::Arm, ENSPartSlot::Leg }` 순회를 `DataSS->GetAllSlotRows()` 기반 순회로 바꿔서, 슬롯이 DT에 추가/삭제되어도 코드 수정 없이 대응 가능하게 함 (`BindToEquipComponent`, `EnsureSlotComponents`, `GetSlotMeshComp`, `HandlePartChanged`, `UpdateSlotVisual`, `ClearSlotVisual`).

## 9. 파츠샵 메인 위젯 — `NSPartEquipWidget`

### `Source/NeoSanctum/UI/Interaction/NSPartEquipWidget.h/.cpp`

이 브랜치에서 가장 많이 바뀐 파일. 세 번의 큰 리팩터를 거침.

**1단계 — 컴포넌트 직접 호출 → ProgressionSubsystem 경유**
원래 `EquipSelectedPart(int32 SelectableIndex)`가 배열 인덱스로 파츠를 골라 `UNSPartEquipComponent::Server_RequestEquip`을 직접 호출하던 구조를, `RequestUnlockPart(Definition)`/`RequestEquipPart(Definition)`가 `NSProgressionSubsystem`(세이브 기반 구매/장착)을 경유하도록 전면 교체.

**2단계 — 선택 모델 도입 (카탈로그 클릭 → 중앙 패널 → 장착 버튼)**
항목별 개별 버튼+hover 방식을 버리고, `BuildPartEntries()`로 `BodyListContainer`/`ArmListContainer`/`LegListContainer` 3분할 카탈로그 구성, `SelectCatalogPart(Row)`로 선택 시 중앙 패널(`SelectedDetailWidget`) 갱신, `OnEquipButtonClicked()`로 구매/장착 확정. 왼쪽 "장착중" 3박스는 `SelectEquippedSlot(SlotTag)`로 클릭한 슬롯에 장착된 것만 표시.

**3단계 — 슬롯 언락/해제를 같은 선택 흐름에 통합 (이번 세션 핵심 작업)**

- `ENSPartSelectionMode`(`None`/`Part`/`SlotUnlock`/`UnequipPart`) 신설 — 중앙 패널/버튼이 가리키는 대상을 하나의 상태로 관리
- `RefreshEquippedDisplay()` — 왼쪽 패널을 슬롯버튼 클릭과 무관하게 "현재 장착 파츠"만 상시 표시하도록 단순화 (기존 `SelectEquippedSlot`을 대체)
- `RefreshEquippedSlotButton()` — 왼쪽 3개 슬롯버튼(`NSPartSlotButton`)에 실제 장착 파츠의 아이콘/이름/수치를 표시
- `OnSlotButtonClicked(SlotTag)` — 슬롯버튼 3개 공용 처리: 잠긴 슬롯 클릭 시 언락 정보 표시, 해금+장착된 슬롯 클릭 시 해제 정보 표시, 해금+빈 슬롯은 무반응
- `RefreshEquipButton()` — 슬롯해금/해제/슬롯해금필요/구매/장착 5가지 상태로 확장
- `RequestUnequipPart()` 신설 — null Definition으로 `SetEquippedPart` 호출해 해제
- `IsSlotEquipped(SlotTag)` — 이 슬롯에 지금 뭐가 장착돼있는지 BP에서도 조회 가능하게 노출 (슬롯버튼 활성 표시용)
- `RefreshSelectionHighlights()` — 카탈로그 선택/슬롯버튼 선택 하이라이트가 서로 배타적으로 켜지고 꺼지도록 정리
- 죽어있던 `NSPartSlotEntryWidget`/`SlotListContainer`(별도 슬롯 언락 리스트, WBP에 배치가 안 돼서 한 번도 작동한 적 없던 코드) 완전 삭제
