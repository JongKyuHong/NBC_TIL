# check, verify, ensure 차이

## check

코드가 반드시 지켜야 하는 전제를 확인할때 씀
`check(Inventory != nulltr);`이거는 이 지점까지 왔다면 인벤토리가 준비돼 있어야 한다는 뜻
개발중에 전제가 깨지면 그 자리에서 멈추므로 원인을 찾기가 쉬움

`Inventory != nullptr`은 값을 확인하기만 하므로, Shipping에서 이 검사가 빠져도 인벤토리를 만드는 작업에는 영향이 없다.

## verify

괄호 안의 작업 자체가 출시 빌드에서도 실행돼야 할 때 씀
`verify(LoadSettingsFromDisk());` 는 개발 빌드와 Shipping 모두에서 파일을 읽음. 개발 중 읽기에 실패하면 그 자리에서 멈춤, 기본 Shipping에서는 읽기에 실패해도 다음 줄로 진행

출시버전에서 파일이 없을때 기본 설정을 적용해야 한다면, 반환 값을 if로 검사해서 기본 설정을 적용하는 코드를 별도로 작성해야 한다.

## ensure

문제가 생겼다는 기록을 남기면서 복구할 수 있을때 씀

```c++
if (ensure(HealthBar != nullptr))
{
    HealthBar->SetPercent(HealthRatio);
}
```

HealthBar가 nullptr이면 ensure가 false를 반환해서 if 본문을 건너뜀, 갱신을 건너뛰게 하는 건 바깥의 if
ensure만 한줄 쓰고 다음 줄에서 HealthBar를 사용하면 그 줄까지 그대로 실행 됨
