# check, verify, ensure 차이

## check

코드가 반드시 지켜야 하는 전제를 확인할때 씀
`check(Inventory != nulltr);`이거는 이 지점까지 왔다면 인벤토리가 준비돼 있어야 한다는 뜻
개발중에 전제가 깨지면 그 자리에서 멈추므로 원인을 찾기가 쉬움

`Inventory != nullptr`은 값을 확인하기만 하므로, Shipping에서 이 검사가 빠져도 인벤토리를 만드는 작업에는 영향이 없다.

## verify

괄호 안의 작업 자체가 출시 빌드에서도 실행돼야 할 때 씀
`verify(LoadSettingsFromDisk());` 는 개발 빌드와 Shipping 모두에서 파일을 읽음. 개발 중 읽기에 실패하면 그 자리에서 멈춤, 기본 Shipping에서는 읽기에 실패해도 다음 줄로 진행

출시버전에서 파일이 없을때 기본 설정을 적용해야 한다면, 반환 값을 if로 검사해서 기본 설정을 적용하는 코드를 별도로 작성해야 한다.

## ensure

문제가 생겼다는 기록을 남기면서 복구할 수 있을때 씀

```c++
if (ensure(HealthBar != nullptr))
{
    HealthBar->SetPercent(HealthRatio);
}
```

HealthBar가 nullptr이면 ensure가 false를 반환해서 if 본문을 건너뜀, 갱신을 건너뛰게 하는 건 바깥의 if
ensure만 한줄 쓰고 다음 줄에서 HealthBar를 사용하면 그 줄까지 그대로 실행 됨

# 메모리 순서와 release/acquire

`std::atomic`을 사용하면 해당 변수의 읽기·쓰기를 원자적으로 처리할 수 있다. 다른 변수까지 안전하게 전달하려면 스레드 사이의 메모리 순서도 보장해야 한다.

## memory_order_relaxed

해당 atomic 변수의 연산을 원자적으로 처리한다. 다른 데이터의 쓰기와 읽기 사이에는 동기화 관계를 만들지 않는다.

따라서 일반 변수에 데이터를 쓰고, relaxed로 준비 완료를 알리는 것만으로는 다른 스레드가 그 데이터를 안전하게 읽는다고 보장할 수 없다.

## release와 acquire

데이터를 준비한 쪽은 `release`로 준비 완료 신호를 저장한다. 사용하는 쪽이 `acquire`로 그 신호를 읽으면, 신호 이전에 기록한 데이터를 안전하게 읽을 수 있다.

```cpp
// 두 스레드를 시작하기 전에 초기화
int Data = 0;
std::atomic<bool> Ready{false};

// 로딩 스레드
Data = 42;
Ready.store(true, std::memory_order_release);

// 사용하는 스레드
if (Ready.load(std::memory_order_acquire))
{
    Use(Data);
}
```

이 예제는 준비 완료 이후 `Data`를 다시 수정하지 않는 조건이다.

`release`로 저장한 `true`를 `acquire`로 읽으면, `Data`에 쓰는 작업이 `Data`를 읽는 작업보다 먼저 일어났다는 **happens-before 관계**가 성립한다.

# DLL과 Windows 로더

## DLL

**Dynamic-Link Library**, 동적 연결 라이브러리다. 컴파일한 함수와 데이터를 별도 `.dll` 파일에 담아 프로그램에서 불러와 사용할 수 있다.

예를 들어 오디오 기능을 `Audio.dll`로 분리하면, 게임이 사용하는 함수와 바이너리 호환성을 유지하면서 해당 DLL을 따로 업데이트할 수 있다.

## Windows 로더

프로그램이 DLL 안의 함수를 실행할 수 있도록 준비하는 운영체제 구성 요소다.

- 필요한 DLL 파일을 찾는다.
- DLL의 코드와 데이터를 프로세스의 가상 주소 공간에 매핑한다.
- 필요한 다른 DLL을 불러오고 주소 정보를 처리한다.
- 프로그램이 호출할 함수의 실제 주소를 연결한다.
- DLL 초기화를 수행한다.

실행 파일을 시작할 때 연결하는 방식에서는 가져올 함수의 주소를 **Import Address Table(IAT)**에 연결한다.

실행 중 코드에서 직접 불러올 때는 `LoadLibrary()`로 DLL을 로드하고, `GetProcAddress()`로 외부에 공개된 함수의 주소를 얻어 호출할 수 있다.
