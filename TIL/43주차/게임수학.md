## 선형 결합

aA + bB 처럼 벡터들을 몇배 해서 더하는것
Forward / Right / Up으로 이동 방향 생성

## Span

주어진 벡터들의 선형 결합으로 만들 수 있는 모든 범위

## 선형 독립

어떤 벡터도 달느 벡터들의 조합으로 대체할 수 없는 상태
제대로 된 2D/3D 좌표계를 만들 수 있는지 판단

## Basis 기저

공간 전체를 표현할 수 있는 선형 독립 벡터 집합
Local/World/Camera 좌표계

## Orthogonal Basis

Basis 축들이 서로 90도
좌표계 구성

## Orthonormal Basis

서로 90도이면서 각각 길이 1
캐릭터/카메라 Forward / Right / Up, 회전 행렬

## Gram-Schmidt

벡터에서 다른 축 방향 성분을 제거해서 서로 수직으로 만드는 방법
망가진 좌표축 보정, 카메라/표면 Basis 생성

## 행렬 Matrix

숫자 배열이면서, 게임수학에서는 여러 Basis/변환을 한 번에 담는 구조
회전, 스케일, 좌표변환, 카메라 등

## Transpose

행과 열을 서로 교환
역행렬/Normal 변환/직교 행렬에서 중요

## Identity Matrix

곱해도 아무것도 바꾸지 않는 행렬

---

X = (1, 0, 0)
Y = (0, 1, 0)
일때 둘을 외적하면 두 벡터 모두에 90도인 새로운 방향 벡터 (0, 0, 1)이 나온다.
또 벡터는 A x B = -(B x A)라는 성질 잊지 말자

Normal은 게임에서 정말 많이 사용한다. 삼각형의 세점에서
E1 = P1 - P0, E2 = P2 - P0으로 두 변을 만든 다음 N = E1 x E2하면 그 삼각형 표면에 수직인 방향이 나온다.

이 Normal은

```
빛이 표면에 얼마나 정면으로 들어오는가?
충돌 후 어느 방향으로 밀어내는가?
벽을 따라 어느 방향으로 미끄러져야 하는가?
```

## 행렬 x 벡터

열벡터 convention

```
    [2 0]
M = [0 3]

    [4]
V = [5]

     [2 0][4]
MV = [0 3][5]
```

계산은 행과 열의 내적이다.
첫번째 결과 2 x 4 + 0 x 5 = 8
두번째 결과 0 x 4 + 3 x 5 = 15

```
     [8]
MV = [15]
```

여기서 행렬의 열은 E1 = (2, 0), E2 = (0, 3), 그리고 입력벡터 V = (4, 5)이다.
즉, 첫번째 Basis를 4배, 두번째 Basis를 5배 사용하겠다라는 의미

MV = 4E1 + 5E2라는 선형 결합을 자동으로 계산한 것

## 행렬은 벡터의 Basis를 바꿔버린다고 볼 수 있음

Identity를 생각해보면 X = (1, 0), Y = (0, 1) 이다.
V = (3, 2)를 곱하면 IV = 3X + 2Y = (3, 2)

행렬이 만약 E1 = (0, 1), E2 = (-1, 0)이다. 그러면
MV = 3E1 + 2E2 = (-2, 3)이 된다.
원래 (3, 2)였던 벡터가 (-2, 3)이 된다. 이는 90도 회전한 결과

## Rotation Matrix

```
    [0 -1]
R = [1 0]
```

R에 X축벡터 = (1, 0)를 곱하면 RX = (0, 1) 즉 Y축벡터가 된다.
Y축(0, 1)을 곱하면 RY = (-1, 0) 즉 Y -> -X
그래서 이 행렬은 Basis 자체를 90도 돌려놓은 변환이라고 볼 수 있다.

## 행렬 X 행렬

```
    [1 2]
A = [3 4]
    [5 6]
B = [7 8]
```

AB를 계산하면 A의 1행과 B의 1열 내적 1 x 5 + 2 x 7 = 19
1 x 6 + 2 x 8 = 22, 3 x 5 + 4 x 7 = 43, 3 x 6 + 4 x 8 = 50

```
     [19 22]
AB = [43 50]
```

행렬곱 AB는 A의 열 개수와, B의 행개수가 같으면 진행가능
행렬곱은 순서가 바뀌면 성립하지 않음 AB != BA

## 결론

> 행렬 × 벡터는 행렬 안의 Basis들을 벡터의 좌표값만큼 선형 결합하는 것이다.
> 행렬 × 행렬은 여러 변환을 하나의 변환으로 합성하는 것이다.
> 행렬 곱은 일반적으로 순서를 바꾸면 결과가 달라진다.

## 상황 A - 벽에 부딪혔는데 벽 방향을 어떻게 알 수 있는가?

게임에서 캐릭터가 삼각형으로 이루어진 벽에 부딪혔다고 가정하하자

```
P0 = (0, 0, 0)
P1 = (0, 3, 0)
P2 = (0, 0, 2)
```

세점이 이렇다고 하자
우리가 원하는것은 `이 벽이 어느 방향을 보고 있는가?` 이다.
왜 필요할까?

예를들어 캐릭터가 벽에 박혔을 때

```
캐릭터 이동 방향
      ↘
       ↘
        | 벽
        |
← Normal
```

벽의 Normal을 알면

- 캐릭터를 벽 밖으로 밀어낼 방향
- 벽 방향 성분을 제거해서 Sliding할 방향
- 총알이 튕기는 방향
- 조명 계산

등에 사용할 수 있다.

### 두 변부터 만든다.

점 자체에는 `방향`이 없다.

그래서

```
E1 = P1 - P0
E2 = P2 - P0
```

을 만든다.

계산하면

```
E1 = (0, 3, 0)
E2 = (0, 0, 2)
```

이제 두 벡터 모두 벽 표면 위에 있다.
그러면 E1 x E2를 계산한다. -> (6, 0, 0)
즉 X방향이다.

Normalize하면 N = (1, 0, 0)
그래서 이 벽의 Normal은 +X 방향이라고 판단할 수 있다.

### Cross의 순서를 반대로 하면?

CrossProduct(Edge2, Edge1)
을하면

(-1, 0, 0) 방향이 된다.
외적은 인자 순서가 실제 의미를 가진다.
이게 삼각형 정점 순서가 중요한 이유

그래서 카메라/시선이 벽의 앞면을 바라볼 때 정점이 P0 -> P1 -> P2으로 배치되도록 폴리곤을 만듬

## 상황 B - 캐릭터가 회전했는데 W키는 어디로 이동해야 하는가?

이번에는 캐릭터가 있다.
처음에는 World 기준으로

```
Forward = (1, 0, 0)
Right = (0, 1, 0)
Up = (0, 0, 1)
```

이라고 했을때

```c++
// W를 누르면
Move += Forward * InputY;

// D를 누르면
Move += Right * InputX;
```

가 될 수 있다.

W와 D를 동시에 누른다면

```
Move = Forward + Right
즉, (1, 0, 0) + (0, 1, 0) = (1, 1, 0) 이다.
```

이게 선형 결합이다.

### Span은 여기서 무엇을 의미하나?

Forward와 Right 두 개만 사용한다면

```
aForward + bRight
```

로 만들 수 있는 방향은 전부 바닥 평면 위다.
즉, Up/Down 방향은 만들 수 없다.

```
Forward + Right
       ↓
바닥 평면에서 모든 방향 표현 가능
```

이게 두 벡터의 Span이다.

게임 개발 관점에서는

> 현재 가진 방향축들로 어느 범위까지 움직임이나 좌표를 표현할 수 있느냐

### 왜 선형 독립이 필요할까?

만약 캐릭터의 Forward와 Right가 실수로

```
Forward = (1, 0, 0)
Right = (2, 0, 0)
```

이 되어버렸다고 하자
D를 눌러도 사실 Forward방향으로 움직인다.
Right가 Forward에 2배일뿐 새로운 방향을 하나도 제공하지 않고 있기 때문에 이 둘은 선형 종속이다.

```
Forward = (1, 0, 0)
Right = (0, 1, 0)
```

이렇게 되면 서로 독립이라 X/Y평면의 모든 방향을 만들 수 있다.

### Basis는 캐릭터의 기준 방향들

```
Forward
Right
Up
```

캐릭터가 세 방향을 가지고 있고, 이 세방향으로 3D공간의 모든 방향을 표현할 수 있다면 이 세벡터는 하나의 Basis다.

**World Basis와 Character Basis는 다를 수 있다.**

캐릭터가 90도 회전했다고 했을때

```
World X -> 동쪽
World Y -> 북쪽
```

World기준에서는 이렇다고 하면
캐릭터가 북쪽을 보고 있으면

```
Character Forward = World Y
```

가 된다. 그러면 캐릭터 Local 좌표에서 (1, 0, 0)
즉 내 앞쪽 1이라는 벡터는 World에서는 (0, 1, 0) 이 될 수 있다.

Local -> World 변환의 핵심
같은 숫자 (1, 0, 0)이라도 어느 Basis 기준으로 쓰였는가에 따라 실제 방향이 달라질 수 있다.

### Orthonormal Basis

Forward, Right, Up이 각각 길이 1이고 서로 90도라면 Orthonormal Basis다.

이 상태에서는 계산이 엄청 편하다
예를 들어 어떤 Velocity가 있고 이 중 `Forward 방향 속도만 얼마냐?`가 궁금하다고 한다면

```c++
float ForwardSpeed =
    FVector::DotProduct(Velocity, Forward);
```

하면 된다. Forward가 단위 벡터이고 나머지 축과 수직이기 때문에

```
Velocity = 5Forward + 2Right
Velocity⋅Forward=5
```

즉 캐릭터 기준 전진 속도는 5다.

이래서 Basis를 서로 수직 + 길이 1 상태로 유지하는것이 편하다.

### Gram-Schmidt

캐릭터나 카메라 축이 계산 과정에서 약간 틀어졌을때

```
Forward=(1,0,0)
Right=(1,1,0)
```

Right가 약간 Forward쪽으로 기울어져 있다.
우리는 Right에서 Forward방향 성분을 제거할 수 있다.

```
Right′=Right−projForward​(Right)
Right′=(0,1,0)
```

> 삐뚤어진 좌표축을 다시 반듯하게 만드는 방법
