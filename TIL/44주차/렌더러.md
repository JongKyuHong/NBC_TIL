# 튜토리얼 3

## 화면에 무엇인가 그리기 위한 3요소

## Device

리소스 공장, 텍스트/버퍼/셰이더 등 리소스를 생성, 스레드-세이프

## Device Context

명령 발행자, 실제 렌더링 명령(Draw, Set, Clear), 스레드-언세이프
DX11부터 생성(Device), 명령(Device Context)로 나뉨

## Swap Chain

게임 화면을 GPU가 바로 모니터에 한 픽셀씩 그리는게 아니고, 먼저 메모리에 있는 이미지에 그림을 완성한다.
그게 Back Buffer, BackBuffer 결과를 모니터에 표시

D3D11CreateDeviceAndSwapChain() 으로 한번에 세 객체를 동시에 만듬

Device = 만든다, Context = 그린다, Swap Chain = 보여준다.

## 흐름

```
1. 내 컴퓨터의 GPU/모니터 정보를 찾는다
2. DX11 렌더링에 필요한 핵심 객체를 만든다.
3. GPU가 어디에 색과 깊이를 기록할지 정한다
4. 매 프레임 그 결과를 화면에 보여준다.
```

## DXGI Factory

왜 이것부터 만들게 될까?
컴퓨터의 그래픽 환경을 조사

```
Factory
   ↓
Adapter(GPU)
   ↓
Output(모니터)
```

> DX11 초기화 전에 DXGI를 이용해 현재 그래픽 환경을 조사한다.

## DX11 렌더링 객체 만들기

```
D3D11CreateDeviceAndSwapChain(...)
```

해당함수로 핵심적 객체 3개를 얻음

## GPU는 어디에 그림을 그리는가?

백버퍼에 그린다.
현재 모니터에 Frame100이 보이는데 GPU는 Frame101을 어딘가에 미리 그리고 있어야 한다.
101을 그리는 공간이 Back Buffer라고 생각하면 된다.

## RTV(Render Target View)

백버퍼는 텍스처라는 리소스이다. 이 텍스처를 이번 렌더링의 색깔 출력 장소로 이동하라 고 알려주기 위한 인터페이스가 Render Target View(RTV, 렌더 타깃 뷰)이다.

```
Back Buffer
실제 이미지 데이터

      ↓ RTV를 만들어

Render Target으로 사용
"여기에 픽셀 색을 써라"
```

## 색깔만 저장하면 끝인가?

아님
3D에서는 물체가 앞뒤로 겹친다.

예를 들어

```
적A 거리 3
적B 거리 10
```

둘이 화면에서는 같은 픽셀을 차지할 수도 있다.
그러면 GPU가

```
A가 앞이네
-> A를 보여줌
```

그래서 별도로 Depth Buffer(깊이 버퍼)를 만든다.
결과적으로 GPU가 쓰는 중요한 공간이 두개가 된다.

```
Render Target
-> 최종 픽셀 색깔 저장

Depth Buffer
-> 각 픽셀의 깊이 저장
```

```c++
OMSetRenderTargets(
    ...RenderTargetView...,
    ...DepthStencilView...
);
```

해서 둘을 렌더링 파이프라인에 연결한다.

> 앞으로 색은 여기에 쓰고, 깊이는 여기에써라
