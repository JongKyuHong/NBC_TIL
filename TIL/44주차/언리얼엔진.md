# Build.cs에서 PublicDependencyModuleNames와 PrivateDependencyModuleNames의 차이

PublicDependencyModuleNames는 내 모듈의 Public헤더가 그 모듈의 타입이나 헤더를 외부에 노출해서 쓰는 경우
PrivateDependencyModuleNames은 내 모듈 내부 구현인 cpp나 Private 헤더에서만 쓰는 경우

```
MyModule/
├─ Public/
│  └─ MyClass.h
├─ Private/
│  ├─ MyClass.cpp
│  └─ InternalHelper.h
└─ MyModule.Build.cs
```

보통 언리얼 모듈에서 이렇게 나누는데 Public/은 다른 모듈에서도 사용하게 공개할 헤더를 넣고, Private/은 현재 모듈내부 구현에서만 사용할 헤더와 cpp를 두는 곳

모듈에서 Public/ Private/구조를 안쓰는 경우도 있는데 그것은 Private모듈이라고 보면 된다.

> Public = 다른 Module에게 보이는 인터페이스
> Private = 내 Module 안에서만 쓰는 구현

# ModuleName_API 붙이는 이유

```c++
class MYGAME_API UMyClass
{
};
```

`MYGAME_API`는 이 클래스의 심볼을 다른 Module에서도 사용할 수 있도록 Export/Import 처리하는 매크로
