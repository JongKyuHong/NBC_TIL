# atomic

atomic은 단순한 read -> +1 -> write 세단계가 따로 노출되는것이 아니라 하나의 atomic read-modify-write(원자적 읽기-수정-쓰기) 연산으로 처리된다.

# 스레드 프로세스간 컨텍스트 스위칭

단순 암기로 하다보니까 맨날 까먹음 실습을 하거나 해야될거 같음

> 프로세스는 `메모리 공간`을 가지고, 스레드는 그 메모리 공간 안에서 `어디까지 실행했는지`를 가진다.

## 왜 스레드마다 Stack이 따로 있는가?

```c++
void Foo()
{
    int x = 10;
}
```

스레드 A도 Foo() 실행, 스레드 B도 Foo()를 실행하는데 둘이 같은 스택영역을 공유하면 x, 함수 호출정보, 반환 주소등이 서로 섞인다 그래서 스레드는 각자마다 스택영역을 가지고 있다.
`내가 어떤 함수에 있고 지역변수가 무엇인가?`

## CPU Register State

```c++
int a = 10;
int b = 20;
int c = a + b;
```

스레드 A가 위 블록을 실행하다가 스레드 B로 전환된다고 해보자
나중에 A로 돌아왔을때 CPU는 A가 어디까지 작업했는지를 알아야 한다.
그래서 Context Switch때 A가 사용하던 레지스터값을 저장해두고 다시 A가 실행될 때 복원함
보통 커널 스택과 TCB(Thread Control Block, 스레드 제어 블록)같은 구조에 나눠 저장한다.

## PC(Program Counter)

> 다음에 어떤 명령을 실행해야 하는가?

에 대한 정보

```c++
A();
B();
C();
```

스레드가 B() 실행중에 멈췄다면 나중에 다시 실행할때 A()를 다시 실행하지 않도록 CPU가 위치를 기억함 이를 Program Counter라고 한다.

그래서 이것도 스레드별로 달라야 한다.

## TLS(Thread Local Storage)

스레드 지역 저장소

```c++
thread_local int Value = 0;
```

라고 하면 변수 이름은 하나인데 스레드마다 자기 `Value`를 따로 가짐
전역 변수처럼 편하게 쓰고 싶은데 스레드끼리는 공유하고 싶지 않은 데이터를 뜻함

## 공유하는 것들

Code영역, 글로벌/데이터 영역, 힙영역은 공유한다.

특히 힙은 여러 스레드에서 힙 객체에 접근해서 발생하는 데이터 레이스같은것으로 유추할 수 있다.

- Code 영역
  프로그램의 실행 코드가 들어가는 영역
  컴파일된 뒤의 기계어 명령어가 들어감
  CPU가 이 주소의 명령 실행 -> 다음 명령 실행 -> 다음 명령 실행 하면서 읽어가는 영역
  여러 스레드가 같은 함수를 실행하더라도 같은 Code영역을 공유함, Thread A와 Thread B가 동시에 `Add()`를 실행한다고 해서 `Add()`코드가 두 벌 생기는건 아니다.

- Data 영역
  초기값이 지정된 전역 변수 / static 변수가 들어감

  ```c++
    int GlobalHp = 100;
    static int EnemyCount = 10;
  ```

  프로그램이 시작할 때 이미 초기값을 가지고 있어야 하니까 실행 파일에도 그 초기 데이터가 저장돼 있음

- BSS영역
  전역/static 변수긴 한데 초기값이 없거나 0인 경우

  ```c++
    int GlobalScore;
    static int Count;

    int value = 0;
  ```

  보통 이런것들이 BSS쪽에 들어갈 수 있음
  왜 Data영역과 나뉘나면 실행파일에

  ```
    0 0 0 0 0 0 0
  ```

  를 전부 저장할 필요가 없기때문

  > 이영역은 시작할 때 0으로 채워
  > 라고 정보만 남겨두면 실행파일 크기를 줄일 수 있다.

- Read-only Data 영역
  문자열 리터럴이나 읽기 전용 데이터가 들어감
  ```c++
  const char* Message = "Hello";
  ```
  여기서 Hello같은 문자열 데이터가 대표적

# 외적

```
X → Y → Z → X
```

순서대로 외적하면 다음 축이 나온다.

X x Y -> Z
Y x Z -> X
Z x X -> Y

반대로 하면 -가 붙고, 자기 자신과 외적하면 0이다.


0  0 1 | 0 
-1 0 0 | 0
0 1 0  | 5


먼저 핵심을 일상적인 말 한 문장으로 설명한다.
처음부터 공식이나 전문용어로 시작하지 않는다.
내가 지금 무엇을 이해하면 되는지 먼저 알려준다.
가능하면 하나의 직관이나 상황을 정하고 설명이 끝날 때까지 유지한다.
공식은 의미를 설명한 뒤 보여준다.
공식을 먼저 제시하고 나중에 해석하지 않는다.
한 번의 설명에서는 하나의 핵심 질문만 해결한다.
추상적인 설명보다 구체적인 숫자 예시를 먼저 사용한다.
설명 중 "당연히", "사실", "즉"이라고 하면서 중간 논리를 건너뛰지 않는다.
내가 "왜?"라고 물을 가능성이 있는 변환은 한 단계 더 풀어서 보여준다.
같은 내용을 여러 표현으로 반복하지 않는다.
핵심 설명이 끝났으면 짧게 정리하고 종료한다.
불필요한 비유, 장황한 부연, 주변 지식은 최소화한다.
설명의 목표는 "공식을 외우게 하는 것"이 아니라 내가 공식을 까먹어도 원리에서 다시 복구할 수 있게 하는 것이다.
