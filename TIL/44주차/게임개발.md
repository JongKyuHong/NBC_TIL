# 운영체제 / 메모리

## TLB Miss

게임이 실행 중인데 물리 메모리는 아직 충분히 남아 있다.

그런데 특정 시스템이 매우 넓은 메모리 영역을 랜덤하게 계속 접근하자 CPU 성능이 크게 떨어졌다.

프로파일링해보니 일반적인 L1/L2 Cache Miss뿐만 아니라 가상 주소 → 물리 주소 변환 쪽에서도 비용이 많이 발생하고 있다.

이 상황에서 CPU 내부의 어떤 구조가 문제가 되고 있을 가능성이 있는지, 그리고 그 구조가 원래 어떤 역할을 하는지 설명해봐.

---

TLB가 충분히 못맞혀서 페이지 테이블을 자주 다시 찾아가는 상황을 의심

가상주소
-> TLB에서 최근 주소 변환 결과 확인
-> 있으면 바로 물리주소 사용
-> 없으면 TLB Miss
-> 페이지 테이블을 따라가서 물리 주소를 찾음(Page Table Walk)
-> 결과를 TLB에 저장

넓은 메모리를 랜덤하게 접근하면 서로 다른 페이지를 너무 많이 건드려 TLB에 주소 변환 정보가 잘 남지 못하고, Page Table Walk가 자주 발생해서 느려질 수 있음

`페이지 폴트랑은 다름`

- TLB Miss : 주소 변환 정보가 TLB에 없음 -> 페이지 테이블을 찾아봄
- Page Fault : 페이지 테이블을 확인했는데 현재 접근 가능한 물리 페이지 매핑 자체가 없음 -> OS개입

## Preemptive Scheduling(선점형 스케줄링)

한 스레드가 CPU를 오래잡고 있으면 다른 스레드들이 기다릴 수 있다. 그래서 운영체제가 일정 조건에서 현재 실행중인 스레들의 PCU사용을 중단시키고 다른 스레드에게 CPU를 넘긴다.

## Interrupt(인터럽트)

- Polling방식

키보드 입력이 들어왔을때 CPU가 계속

```
입력 왔나? → 안 옴
입력 왔나? → 안 옴
입력 왔나? → 안 옴
```

CPU가 계속 상태를 확인하는걸 폴링이라고 한다.

- 인터럽트 방식

CPU가 다른 작업 수행
-> 키보드 입력 발생
-> 하드웨어가 CPU에 인터럽트 신호 전달
-> CPU가 입력 처리 루틴 실행

이벤트가 드물게 발생하는 상황에서는 계속 확인할 필요가 없어서 효율적일 수 있다.

## RAW의존성

Read After Write 의존성

- 뒤 명령이 앞 명령의 결과를 기다려야 해서 CPU가 여러 명령을 동시에 겹쳐 처리하기 어려운 예시

```c++
A = B + C;
D = A * 2;
E = D + 10;
F = E * 3;
```

CPU는 원래 여러 명령을 동시에 진행시키는 Instruction-Level Parallelism(명령어 수준 병렬성)을 활용하려고 하는데, 이런 의존성이 길게 이어지면 그 효과가 줄어든다.

```c++
A = B + C;
D = E + F;
G = H * I;
J = K + L;
```

이런경우는 Instrcution-Level Parallelism(명령어 수준 병렬성)이 잘 나오는 경우

# 네트워크

## Server Rewind(서버 되감기), Lag Compensation(지연 보상)

플레이어 A가 총을 발사
-> 패킷이 서버까지 50ms 걸림
-> 그동안 적은 이미 이동함
-> 서버 현재 위치만 보면 빗나감

그런데 플레이어 입장에서는 분명히 보고쐈는데 네트워크 지연때문에 안맞은 것처럼 보이는 문제가 생김
그래서 서버가 최근 상태를 잠시 저장해둔다.
예시

```
12:00:00.000 적 위치
12:00:00.016 적 위치
12:00:00.032 적 위치
12:00:00.048 적 위치
```

그리고 A의 발사 요청이 도착하면 서버가 대략

이총은 50ms 전에 발사됐구나 라고 판단해서 50ms 전 적의 위치/히틉막스를 되돌려서 명중 여부를 검사

클라이언트 발사
-> 서버에 발사 시각/정보 도착
-> 서버가 과거 상태 조회
-> 당시 적 Hitbox 기준으로 판정
-> 명중 여부 결정

`높은 Ping때문에 공격자가 지나치게 불리해지는 걸 줄이기 위함`

하지만 단점은 Ping이 높은 플레이어가 쏜 총 때문에 상대 입장에서 피했는데 왜맞음? 상태가 될 수 있다.
그래서 실제 게임에서는 보통 되감기 가능한 시간을 제한하거나, 너무 높은 Ping은 완전히 보상하지 않는식으로도 개발함

## Extrapolation, Dead Reckoning

Extrapolation(외삽), Dead Reckoning(추측 항법)

원격 플레이어의 다음 위치 패킷이 아직 안 왔을때 이전 속도/방향으로 미래 위치를 추정하는 방식

- Interpolation(보간) : 이미 받은 두 상태 사이를 채움
- Extrapolation(외삽) : 마지막 상태를 기준으로 미래를 예상
- Client-side Prediction : 내 입력 결과를 서버 응답 전에 먼저 반영
