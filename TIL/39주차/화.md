# 언리얼 개념

## ShouldCreateSubsystem

Subsystem인스턴스를 실제로 만들지말지 결정하는 함수
기본적으로 Subsystem은 엔진이 클래스를 발견하면 Owner가 생성될때 자동으로 인스턴스를 만들어줌, 근데 이게 항상 필요한게 아니기때문에
ShouldCreateSubsystem()을 오버라이드해서 조건을 건다.

```c++
virtual bool ShouldCreateSubsystem(UObject* Outer) const override
{
    if (!Super::ShouldCreateSubsystem(Outer))
        return false;

    // 전용 서버에서는 UI 관련 Subsystem 필요 없음
    if (IsRunningDedicatedServer())
        return false;

    return true;
}
```

## InitializeDependency

같은 타입의 Subsystem은 초기화 순서가 보장되지 않음 그러므로, Collection.InitializeDependency<T>()를 Super::Initialize 호출전에 선언하면 엔진이 T를 먼저 초기화한 뒤 현재 Subsystem의 Initialize를 이어서 실행한다. 대신 A -> B -> C -> A 이런식으로 순환 의존성은 조심해야됨

## build.cs에서 PublicDependencyModuleNames와 PrivateDependencyModuleNames의 차이

PublicDependencyModuleNames : 내 모듈의 Public헤더에서 그 모듈 타입을 사용, 내 모듈에 의존하는 다른 모듈에게도 그 의존성이 전파도미
PrivateDependencyModuleNames : 내 모듈의 cpp내부에서만 사용, 다른 모듈에는 의존성이 전파되지 않음, 가능하면 Private으로 두는게 빌드 전파가 줄어서 컴파일 속도에도 유리함

예를들면

```c++
// Public/MyWidgetManager.h
#include "Blueprint/UserWidget.h"

class UMyWidgetManager
{
    UUserWidget* Widget;
};
```

이처럼 Public헤더에서 UMG타입이 드러난다면 UMG를 Public Dependency로 잡는 식이다.
Public헤더에서 쓰면 Public, cpp에서만 쓰면 Private이라고 보면된다.

## UCLASS

언리얼 리플렉션 시스템에 클래스를 등록하는 매크로
리플렉션에 등록한 클래스는 엔진이 타입정보, 프로퍼티/함수 메타데이터, 직렬화, 에디터 노출, GC(가비지 컬렉션)추적, 네트워크 복제, 메타데이터 등을 다룰 수 있다.
엔진은 C++그 자체만으로는 위 기능을 일관되게 처리하기 힘들다 그래서 UCLASS/UPROPERTY/UFUNCTION을 명시하면 엔진에서 처리

## GameModeBase

게임 규칙의 권위를 갖는 클래스, 서버에만 존재, 서버만 알면 되는 규칙을 담는다(플레이어 접속시 처리, 플레이어 스폰, 리스폰 규칙, 팀 배정, 점수 규칙, 라운드 진행, 승리 조건 판정 등)
대표적으로 DefaultPawnClass, PlayerControllerClass, HUDClass, GameStateClass 같은 게임 구성을 GameMode에서 지정함

## GameInstance

게임 프로세스(실행)단위로 1개 존재하는 전역 컨텍스트 클래스
게임 시작시 엔진이 생성, 프로세스 전체(레벨 로딩/언로딩과 무관)에 유지, 게임종료시 종료
GameInstance는 서버/클라이언트 각각 자기 프로세스에만 존재한다
복제 대상이 아니므로 모든 클라이언트에서 알아야 하는 상태는 GameInstance에 두면 안됨
GameInstanceSubsystem로 비대해지는것을 방지
어디서든 월드가 있다면 GetGameInstance()로 접근

### 주의점

1. GameInstance에 게임 플레이 공유 상태를 넣는 실수
   -> 이런것들은 GameState로 빼기
2. 레벨 전환시 사라지는 객체를 GameInstance가 그대로 들고있는 문제
   -> 레벨 종속 객체 참조는 `TWeakObjectPtr`로 들고 `IsValid()` 체크
   에셋 참조는 `TSoftObjectPtr` / `TSoftClassPtr`로 들고 필요 시 로드

## HUD

UI진입점, 일반적으로 로컬(해당 플레이어의 클라이언트)에만 존재, 서버/다른 클라이언트에 복제되는 개념이 아님
요즘 프로젝트에는 주로 UMG를 많이 쓰고(Widget), HUD는 위젯을 생성/관리하는 얇은 래퍼로 쓰거나 아예 생략하는 경우도 있다.
입력/상호작용 흐름은 보통 PlayerController <-> Widget 연결이 중심
