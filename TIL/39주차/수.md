### 다형성 문제

```c++
#include <iostream>
using namespace std;

class Base
{
public:
    Base()
    {
        Print();
    }

    virtual void Print()
    {
        cout << "Base";
    }
};

class Derived : public Base
{
public:
    void Print() override
    {
        cout << "Derived";
    }
};

int main()
{
    Derived d;
}
```

- Derived d; 이걸로도 객체 생성이 가능하다.
- 객체 생성순서가 Base의 생성자가 실행 -> Derived 생성자 실행 -> Base의 생성자 내부에서 Print()를 호출하는데 아직 Derived 생성이 끝나지 않아서 가상 함수 호출이 Derived::Print()까지 내려가지 않고 Base::Print()가 호출됨 -> Base출력
- 생성자/소멸자 내부에서 virtual 함수를 호출해도 일반적인 다형성처럼 파생 클래스 함수가 호출되지 않는다.

### OS / Deadlock

```c++
std::mutex mutexA;
std::mutex mutexB;

void Thread1()
{
    mutexA.lock();
    mutexB.lock();

    // 작업

    mutexB.unlock();
    mutexA.unlock();
}

void Thread2()
{
    mutexB.lock();
    mutexA.lock();

    // 작업

    mutexA.unlock();
    mutexB.unlock();
}
```

이 상황에서 두 스레드가 동시에 실행될때 발생할 수 있는 문제는??
-> 데드락 : 왜냐하면 각 스레드가 락을 잡는 순서가 서로 반대임
Thread1은 mutexA획득 -> mutexB기다림, Thread2는 mutexB획득 -> mutexA기다림
가장 좋은 해결법은 모든 스레드에서 락 획득 순서를 통일

### PageFault

PageFault란 프로세스가 접근한 가상 메모리 페이지가 현재 물리 메모리에 없을때 발생할 수 있음

1. CPU가 특정 가상 주소에 접근
2. 페이지 테이블을 확인했는데 해당 페이지가 현재 물리 메모리에 없음
3. Page Fault 발생 -> OS가 처리
4. 필요한 페이지를 디스크등에서 물리 메모리로 가져옴
5. 페이지 테이블을 갱신
6. 중단됐던 명령을 다시 실행

### std::move

std::move란 전달 받은 값을 rvalue reference로 취급할 수 있도록 변환하며, 실제 이동 여부는 이후 호출되는 함수에 달려 있음

#### rvalue / lvalue

lvalue란 이름이 있고, 메모리 어딘가에 계속 존재해서 다시 접근할 수 있는 값
rvalue란 잠깐 만들어졌다가 곧 사라질 임시 값

```c++
std::string a = "hello"; // a는 lvalue
std::string("hello") // rvalue
```
