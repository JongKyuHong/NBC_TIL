# Page Fault

Page Fault는 메모리 접근 처리에 문제가 발생한 경우를 말한다.
CPU가 메모리 접근을 시도했는데 현재 페이지 매핑이나 접근 권한으로는 처리할 수 없어서 발생시키는 예외
시스템콜은 파일입출력 같은걸 시도할때 커널에 서비스를 요청하는 것 둘은 엄연히 다르다.

## 무조건 디스크에서 데이터를 읽어야 하는건 아니다.

Page Fault가 발생했다고 무조건 디스크에서 데이터를 읽는것은 아니다.

1. 해당 페이지에 처음 접근하는 경우
   게임에서 새로운 메모리 공간을 할당 받고, 해당 페이지에 처음 접근하는 경우 Window에서는 Commmit만 해주고 그 순간 물리 RAM이 할당되는건 아니다. 그래서 이때 해당 메모리에 접근하면 Page Fault가 발생할 수 있다.

2. 페이지가 이미 RAM에 있는 경우
   어떤 페이지가 프로세스의 현재 페이지 테이블에는 유효하게 매핑되어 있지 않지만, 실제 데이터는 이미 RAM의 다른 관리 목록에 남아있는 경우, 이 경우 운영체제는 기존 RAM 페이지를 다시 연결하게 된다.

3. Copy-on-Write
   두 대상이 읽기 전용으로 같은 물리 페이지를 공유하고 있을때 한쪽이 데이터를 수정하려고 하면 OS는 Page Fault를 이용해 쓰기 요청을 처리하면서 별도의 물리 페이지를 만들고 내용을 복사할 수 있다.
   즉, 처음에는 같은 메모리를 가리키고 있지만 쓰기작업 후에는 다른 메모리를 가리키는 상태가 된다.

## 디스크에서 데이터를 읽어야 하는 경우

보통 Hard Page Fault라고 부른다. 디스크 읽기가 필요없는 경우는 Soft Page Fault라고 불림

> Page Fault란 CPU가 가상메모리에 올바르게 접근하지 못할때 발생하는 예외를 말한다. 운영체제의 커널은 접근이 유효한지 확인하고 필요한 페이지를 준비한다. 디스크에 존재하면 RAM으로 가져오고, 이미 RAM에 있으면 다시 매핑하고, 한번도 접근하지 않은 페이지면 초기화한다.
