# 회복 아이템 서버 처리

네오생텀에서 회복아이템을 주울때, 클라이언트가 서버 응답을 기다린 다음 아이템을 없애면 사용자입장에서 네트워크 지연만큼 반응이 느려지기때문에 안좋은 경험을 남길 수 있다.
그리하여 클라이언트가 아이템을 주웠다고 판단하는 즉시 화면에서 사라지게끔 처리했다. 하지만 실제 회복 여부는 서버에서 처리한다.
이는 보통 **낙관적 처리(Optimistic Update)** 라고 볼 수 있다. 서버가 성공이라고 응답하기 전에 클라이언트가 먼저 시각적인 변화를 적용하는 방식

```c++
bCollectedRequested = true;

SetActorHiddenInGame(true);
SetActorEnableCollision(false);
```

회복 아이템에 오버랩 되었을때 이런식으로 처리를 해서 게임에서 안보이게 하고, 충돌처리를 제거하는식으로 개발했다. 이때 bCollectedRequested는 서버에서 처리중임을 알리는 변수로 여러번 요청하지 않도록하기위한 bool변수

실제로 검증은 `UNSHealDropSubsystem::TryCollect()`에서 처리했다.

```c++
if (!ApplyHealEffect(Collector, Entry->PotionTag))
{
    if (ANSHealReplicationProxy* Proxy = FindProxy(Collector))
    {
        Proxy->SendRestoreEvent(DropId);
    }

    return false;
}
```

주목할 부분은 이쪽인데 기획에 따라서 풀피일때는 ApplyHealEffect가 실패하고 그에따라서 SendRestoreEvent를 보내서 힐아이템을 복원시키는 작업

`ANSHealReplicationProxy.cpp`에서는 검증 실패한 경우 복원과

```c++
void ANSHealReplicationProxy::
Client_RestoreHeal_Implementation(int32 DropId)
{
    if (TObjectPtr<ANSLocalHealPickup>* Found =
        ActivePickups.Find(DropId))
    {
        if (*Found)
        {
            (*Found)->RestoreVisual();
        }
    }
}
```

검증 성공한 경우 제거 함수를 담고 있다.

```c++
void ANSHealReplicationProxy::
Client_RemoveHeal_Implementation(int32 DropId)
{
    TObjectPtr<ANSLocalHealPickup> Pickup;

    if (ActivePickups.RemoveAndCopyValue(DropId, Pickup)
        && Pickup)
    {
        Pickup->ConfirmCollected();
    }
}
```

여기서 RemoveNadCopyValue는 두번째인자 Pickup에 DropId에 해당하는 TMap의 Value를 부여하고 TMap에서 제거한다. ConfirmCollected함수는 Destroy()가 들어있다.
