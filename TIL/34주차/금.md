# 트러블슈팅 (feature/OutRun-Parts-UI)

아웃런 파츠 상점 UI 리디자인 작업 중 발생한 문제와 원인, 해결 방법 정리.

## 1. 외곽선 PNG 배경이 검은 박스로 나옴

**증상:** `outer_border_only.png`를 UI 프레임으로 임포트해서 쓰면 안쪽은 투명한데 프레임 바깥 여백이 불투명한 진회색(RGB 23,22,20)으로 나와서 검은 박스처럼 보임.

**원인:** 안쪽 영역은 이미 알파 0으로 되어 있었지만, 프레임 바깥 여백이 알파 255(불투명)로 구워져 있었음. 임포트 설정 문제가 아니라 PNG 파일 자체의 알파 채널 문제.

**해결:** 이미지 가장자리에서 시작하는 플러드필로, 배경색과 비슷한 색이면서 가장자리와 연결된 픽셀만 투명화 (프레임 안쪽 디테일은 배경색과 분리되어 있어서 안전). `Docs/outer_border_only_alpha.png`로 저장.

## 2. 투명 여백이 너무 넓음

**증상:** 배경을 투명화한 뒤에도 프레임 바깥으로 여백이 많이 남아서 UMG에서 배치 시 실제 프레임보다 이미지가 훨씬 큼.

**해결:** 알파 채널 기준 bounding box(`getbbox()`)를 구해서 여유 2px만 남기고 크롭. 543×1017 → 496×976.

## 3. SPR_CommonUpgrade_WindowFrame을 작은 영역에 쓰면 찰흙이 됨

**증상:** `SPR_CommonUpgrade_WindowFrame`(1300×200)을 큰 창에서는 잘 쓰다가, 작은 영역에 넣으니 테두리가 뭉개짐.

**원인:** 프레임 이미지를 통짜로 스케일 다운하면 얇은 테두리 디테일이 몇 픽셀로 뭉개지는 게 정상 동작. Draw As가 Image(통짜 스케일)로 되어 있었음.

**해결:**

- Brush의 **Draw As = Box**로 변경, **Margin**을 모서리 장식 비율로 설정 (모서리는 원본 해상도 유지, 변만 늘어남/줄어듦)
- 스프라이트(`SPR_...`) 자체는 Box Margin이 제대로 안 먹는 케이스가 있어서, 브러시에 원본 텍스처를 직접 지정
- 텍스처 설정에서 **Texture Group = UI** 확인 (밉 스트리밍으로 인한 흐림 방지, [[project_part_preview_stage_mip_streaming]]과 같은 계열 문제)

## 4. DT 행을 복사·붙여넣기로 여러 개 만들었는데 상점에 하나만 뜸

**증상:** 암 파츠 테스트용으로 유효한 DT 행을 복사해서 여러 개 넣었는데 실제 상점(카탈로그)에는 반영이 안 됨.

**원인:** `NSDataSubsystem::BuildPartRowCache()`가 캐시를 `TMap<FPrimaryAssetId, FNSPartDefinitionRow>`로 관리하는데, 키가 DT 행 이름이 아니라 **`Row->Definition`(파츠 Definition 에셋 참조)**. 행을 복사하면 행 이름은 달라지지만 `Definition` 필드는 그대로 복사되어 여러 행이 같은 DefId를 가리키게 되고, `TMap::Add`가 마지막 행으로 덮어써서 하나만 남음.

**해결:** 테스트용으로 여러 파츠를 만들려면 각 DT 행마다 **서로 다른 `UNSPartDefinition` 에셋**을 `Definition`에 연결해야 함 (행 이름만 다르고 Definition이 같으면 무조건 1개로 합쳐짐).

## 5. 새로 추가한 파츠가 카탈로그에 안 보임

**원인:** `NSPartEquipWidget::BuildPartEntries()`(`NSPartEquipWidget.cpp:407-428`)에 두 가지 필터가 있음.

- `Pair.Value.bEnabled`가 true여야 함
- `PartSlot` 태그가 `BodySlotTag`/`ArmSlotTag`/`LegSlotTag` 중 하나와 정확히 일치해야 함 (`GetCatalogContainerForSlot`). 컨테이너가 3개로 하드코딩되어 있어서 일치 안 하면 `nullptr`이 되어 그냥 버려짐.

**해결:** DT 행의 `bEnabled` 체크 여부와 `PartSlot` 태그 오타 여부 확인.

## 6. 카탈로그 리스트가 늘어나기만 하고 스크롤이 안 생김

**원인:** `BodyListContainer`/`ArmListContainer`/`LegListContainer`는 C++에서 `UPanelWidget`으로만 바인딩되어 있고, 스크롤 여부는 전적으로 WBP 디자이너 계층 구조에 달림. 리스트 그리드가 `ScrollBox` 없이 바로 부모(`VerticalBox`) 안에 배치되어 있으면 내용물 크기만큼 계속 늘어남.

**해결:** 각 섹션(바디/암/레그)을 개별 `ScrollBox`로 감싸야 함. 전체 패널을 하나의 ScrollBox로 감싸면 안 되고(그러면 개별 섹션이 아니라 패널 전체가 스크롤됨), 섹션별로 각각 감싸야 함.

## 7. ScrollBox는 생겼는데 두 번째 줄이 중간에서 잘림

**원인:** `ScrollBox`를 감싼 고정 높이 위젯이 없어서, 실제 표시 높이가 "행 높이의 배수"가 아니라 애매한 값이 됨. 특히 `VerticalBox`에서 섹션들이 **Fill**로 배분되어 있으면, 높이가 남은 공간 비율로 결정되기 때문에 행 높이와 우연히 맞아떨어지지 않는 한 항상 잘림.

**해결:**

- `ScrollBox`를 `SizeBox`로 감싸고 **Height Override** = `(카드 높이 × N줄) + (세로 간격 × (N줄 - 1))`로 정확히 계산
- `VerticalBox`에서 그 `SizeBox`가 들어간 슬롯의 **Size Rule을 Fill → Auto로 변경** (Fill로 두면 SizeBox의 고정 높이가 무시되고 VerticalBox가 강제로 늘려버림)
- Fill과 "정확한 줄 수 고정"은 근본적으로 상충하는 요구라, SizeBox 같은 고정 높이 위젯 없이는 해결 불가. 줄 수가 늘어날 가능성이 있는 섹션만 최소로 적용.

## 8. 인런 C키 파츠 패널: 미장착 슬롯이 디자인 타임 placeholder 텍스트로 보임

**증상:** 인런에서 C키로 파츠 패널을 열면, 장착된 파츠는 정상 표시되지만 미장착 슬롯은 "텍스트 블록"이라는 기본 텍스트와 흰 배경 아이콘으로 표시됨. `WBP_PartPanel`의 `SlotButtonContainer`는 디자인 타임에 비어있어서 컨테이너 문제는 아니었음.

**원인:** `NSPartPanelWidget::ApplySlot()`(`NSPartPanelWidget.cpp`)이 슬롯에 장착된 파츠가 없을 때 그냥 `return`만 하고 `SlotButton->ClearPart()`를 호출하지 않았음. 그래서 그 버튼은 `SetPart()`/`ClearPart()` 어느 쪽도 호출된 적 없는 상태로 남아, `WBP_PartSlotButton` 템플릿에 디자인 타임 기본값으로 박혀있던 텍스트가 그대로 노출됨.

**해결:** `PartData == nullptr || !PartData->IsValid()` 분기에 `SlotButton->ClearPart();` 한 줄 추가 (수정 완료, 빌드 확인 대기).

## 9. 인런 파츠 상점을 여닫기 반복하면 크래시 (BitArray assert)

**증상:** 인런 파츠 NPC 상점을 열었다 닫았다를 반복하면 `Assertion failed: StartIndex >= 0 && StartIndex <= Array.Num() [BitArray.h:1967]`로 크래시. 콜스택은 `NSPartUpgradeWidget::RefreshEquippedDisplays()` → `NSPartPanelWidget::RefreshEquippedParts()`(`SlotButtonMap` 순회하는 for문)에서 발생.

**원인:** `NSPartUpgradeWidget::SlotButtonContainer`를 `TObjectPtr<UNSPartPanelWidget>`(BindWidgetOptional)로 새로 추가했는데, WBP_PartUpgrade의 Hub 페이지에는 **이전에 실험 삼아 붙여넣었던 이름만 같은 일반 컨테이너(VerticalBox 등)** 가 그대로 남아있었음. UMG의 `BindWidgetOptional`은 **이름으로만** 매칭하기 때문에, 타입이 다른 그 VerticalBox가 그대로 `UNSPartPanelWidget*`에 바인딩됨.

`IsValid(SlotButtonContainer)`는 통과하지만(진짜 UObject이긴 하니까), `RefreshEquippedParts()` 호출 시 VerticalBox의 메모리를 `NSPartPanelWidget`인 것처럼 해석해서 `SlotButtonMap`(TMap) 오프셋 위치에 있는 VerticalBox의 다른 멤버 데이터를 TMap으로 잘못 읽음 → 내부적으로 쓰레기 값이 되어 순회 시 BitArray 인덱스 assert. 힙 상태에 따라 크래시가 나기도/안 나기도 해서 "여닫기를 반복하면" 터지는 것처럼 보였음. `SlotButtonContainer`가 항상 "안 나옴"으로 보였던 것도 같은 원인 — 그 자리에 실제 `WBP_PartPanel`이 없었으니 표시될 게 없었음.

**교훈:** `BindWidgetOptional`/`BindWidget`은 **이름은 맞는데 타입이 다른 위젯**이 WBP에 남아있어도 컴파일 에러 없이 조용히 잘못 바인딩된다. UPROPERTY 이름을 바꾸거나 타입을 바꿀 때는 WBP 쪽에 같은 이름의 옛날 위젯이 남아있지 않은지 반드시 확인해야 함.

**해결:** WBP_PartUpgrade에서 옛 `SlotButtonContainer`(일반 컨테이너) 삭제 → 그 자리에 실제 `WBP_PartPanel`을 배치하고 이름을 `SlotButtonContainer`로 지정.
