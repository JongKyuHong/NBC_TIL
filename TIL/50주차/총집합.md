# 트랜잭션

DB에서 여러 작업을 하나의 작업 단위로 묶어서, 전부 성공하거나 전부 취소되도록 관리하는 것

## 예시

플레이어 A가 플레이어 B에게 1000골드를 주고 검을 구매한다고 했을때

거래 과정이

1. A의 골드에서 1000골드 차감
2. B의 골드에 1000골드 추가
3. B의 인벤토리에서 검 제거
4. A의 인벤토리에 검 추가

여기서 1번만 성공하고 서버 오류로 나머지가 실패한다면?
A는 골드를 잃었는데 검을 받지 못하는 문제가 생길 수 있다 이를 방지하기 위해 트랜잭션을 사용한다.

전부 성공하면 COMMIT, 도중 실패하면 ROLLBACK

## ACID

A : Atomicity, 원자성, 전부 성공하거나 전부 취소
C : Consistency, 일관성, 데이터의 규칙 유지 (골드가 음수가 되는 거래 금지)
I : Isolation, 격리성, 동시에 실행되는 트랜잭션의 간섭(같은 아이템을 동시에 구매하는 문제 방지)
D : Durability, 지속성, 확정된 결과는 장애가 발생해도 보존(거래 완료 후 서버가 재시작해도 결과 유지)

# 데드락 원인 4가지

1. 상호 배제
   하나의 자원을 동시에 한 스레드만 사용할 수 있음
2. 점유와 대기
   자원을 점유한 상태에서 다른 자원을 기다림
3. 비선점
   다른 스레드가 점유한 자원을 강제로 빼앗을 수 없음
4. 순환 대기
   여러 스레드가 서로 상대방의 자원을 기다리는 순환 구조

# 64비트 프로그램과 32비트 프로그램의 차이

- 포인터 크기 차이 (8바이트, 4바이트)
- 이론적 가상 주소 공간 (16EB, 4GB)
- 범용 레지스터 (일반적으로 64비트, 32비트)
- CPU연산시 64비트 정수 연산 지원 or 32비트 연산 지원

# 포트포워딩

# SMT(Simultaneouse Multithreading)

하나의 물리 CPU코어가 여러 개의 하드웨어 스레드를 동시에 처리할 수 있도록 하는 기술

## SMT가 필요한 이유

CPU 코어가 명령어를 실행할 때 항상 모든 연산 장치를 100% 활용하는 것은 아니다
예를들어, CPU가 메모리에서 데이터를 기다리거나, 명령어 간 의존성 때문에 일부 실행 장치를 활용하지 못하는 경우가 있는데 SMT는 이런 여유 자원을 다른 스레드의 명령어를 실행하는데 활용하는 기술이다.

# AABB와 Sphere차이

게임에서 충돌을 검사할 때 자주 사용하는 기본 충돌체

- AABB끼리 충돌하는지 판단
  X,Y,Z 축에서 모두 겹쳐야 충돌
  어느 한 축이라도 서로 떨어져 있다면 충돌하지 않는것임

- Sphere끼리 충돌하는지 판단
  두 구체의 중심 사이 거리 <= 두 반지름의 합이면 충돌
  중심 거리가 8이고, 반지름이 각각 5와 4라면 합이 9니까 충돌하는 것

- 적이 회전하면?
  AABB : 월드 좌표축에 평행해야 하므로 적이 회전하면 이를 감싸는 AABB의 크기가 달라질 수 있음
  Sphere : 회전해도 모양이 동일하므로 중심과 반지름만 같다면 충돌 범위가 변하지 않음

# GPU 렌더링 파이프라인 단계

3D 모델의 정점 데이터를 받아 최종적으로 화면에 표시할 이미지로 만드는 과정

1. Input Assembly
   Vertex Buffer에서 정점의 Position, Normal, UV등을 읽고 Index Buffer를 사용해 어떤 정점들이 도형을 구성하는지 결정

2. Vertex Shader
   정점 하나하나의 위치를 변환, 모델의 로컬 좌표를 월드/뷰/투영 변환을 통해 화면에 투영할 수 있는 클립 좌표로 만듬

3. Primitive Assembly
   Vertex Shader에서 처리된 정점들과 인덱스 정보를 바탕으로 삼각형을 구성
   여기서 삼각형의 정점 3개가 어떤 도형을 이루는지 결정됨

4. Rasterization
   삼각형이 화면의 어떤 픽셀을 덮는지 계산해서 프래그먼트를 만듬
   UV, Normal같은 정점 데이터도 픽셀 위치에 맞게 보간할 수 있음

5. Pixel Shader
   보간된 UV, Normal, 텍스처 등의 정보를 활용해서 프래그먼트의 색상 등을 계산
   무슨 색으로 표현할지 계산하는 단계

6. Output Merger
   깊이 테스트로 앞뒤 관계를 판단, 필요하면 알파 블렌딩 수행
   그 결과를 Render Target에 기록

# World / View / Projection 변환

- World 변환 : 캐릭터를 게임 맵의 `(100, 200, 0)` 위치에 배치하는 과정
- View 변환 : 카메라 입장에서 캐릭터가 어디에 있는지 계산하는 과정, 카메라를 원점으로 생각
- Projection 변환 : 3D 공간을 카메라 화면에 투영할 수 있도록 만드는 과정, 원근 투영에서는 멀리 있는 물체가 작게 보이도록 하는 효과도 여기서 생김
