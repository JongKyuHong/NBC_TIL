# 그래픽스

## 흐름

CPU

- 어떤 물체를 그릴지 결정
- 그 물체의 Vertex Buffer, Index Buffer, Material, Texture같은것을 준비
- GPU에게 그리라고 Draw Call을 보냄

GPU

- Vertex Buffer 읽음
- Vertex Shader로 정점 위치를 화면에 맞게 변환
- Index Buffer를 보고 삼각형 조립
- 삼각형이 화면의 어떤 픽셀을 덮는지 계산(Rasterization) -> Depth Test
- Pixel Shader로 각 픽셀의 최종 색 계산
- Render Target/Back Buffer에 결과 저장

## Render Target, Back Buffer, G-Buffer

RenderTarget

- 가장 큰 개념
- GPU가 렌더링 결과를 써 넣는 대상
- 최종 화면일수도 있고, 중간 계산용 텍스처일 수도 있다.
- G-buffer나 PostProcessing이나 CCTV, 거울, 미니맵등을 만들때 임시로 그려넣어야할때 Render Target에 그리거나 RenderTargetTexture에 그려둠
- 모니터에 보여줄 그림은 Back Buffer고, 중간 RenderTarget은 아직 완성안되었고 다음 렌더링 계산에서 다시 사용할 그림들

Back Buffer

- 최종 화면 출력을 위한 특별한 Render Target
- GPU가 여기다 최종 이미지를 그리고, 나중에 Present해서 모니터에 보여줌
- Back Buffer = 화면에 보여줄 최종 그림 저장소

G-Buffer

- Deferred Rendering에서 쓰는 여러 개의 Render Target의 묶음
- 최종 색을 바로 저장하는게 아니라, 조명 계산에 필요한 중간 정보를 저장

## Mipmapping

텍스처를 여러 크기로 미리 줄여서 저장해두고, 화면에서 작게 보일때 더 작은 버전을 골라 쓰는 것
원본이 1024x1024일때

```
512×512
256×256
128×128
64×64
...
```

이런식으로 작은 버전을 미리 같이 만들어둔다.
왜 쓰냐?
멀리 있는 물체는 화면에서 몇 픽셀밖에 안보이는데 굳이 큰 텍스처를 그대로 샘플링하며 깜빡임, 노이즈, aliasing이 생기기 쉽다.

## Aliasing

화면의 픽셀 수가 부족해서 원래 모양을 제대로 표현하지 못하고, 계단처럼 깨져보이는 현상
꼭 외각선만 문제가 되는건 아니고, 멀리 있는 철망이나 나뭇잎, 바닥 무늬 같은 것도 화면의 픽셀보다 너무 세밀하면 깜빡거리거나 지글거리는 현상이 생길 수 있다.
안티 엘리어싱을 설정하면 주변 픽셀을 참고하거나 여러 샘플을 이용해서 계단 부분을 좀 더 부드럽게 만들어줌

## Depth Buffer

이 픽셀에서 지금까지 가장 앞에 있는 물체가 얼마나 가까운지 기록해두는 메모리
같은 화면위치에 물체 두개가 있을때 GPU는 깊이값을 비교한다. 가까운 물체가 화면에 남는다.

## Deferred Rendering

일단 화면에 보이는 물체들의 재료 정보를 먼저 저장해두고, 조명계산은 나중에 한꺼번에 하자
Forward Rendering은 보통 물체를 그릴때 조명계산을 바로 함

## Vertex가 실제로 무엇을 들고 있는가?

정점은 위치 (x, y, z)하나가 아니다.

```
Position
UV
Normal
```

같은 데이터 묶음이다.

### Vertex Buffer

GPU에게 넘겨줄 정점 창고

```
Vertex Buffer

0 : A
1 : B
2 : C
3 : D
```

실제 정점 데이터를 모아놓는곳

### Index Buffer

Vertex Buffer의 몇번 정점을 쓸지 적어놓은 번호표

```
삼각형 1 = A B C
삼각형 2 = A C D
```

```
Index Buffer

0, 1, 2
0, 2, 3
```

GPU는 이걸보고

```
0 -> A
1 -> B
2 -> C

=> A B C 삼각형
```

을 만든다. 몇번 정점을 어떤 순서로 사용할지 적어둔 번호표라고 보면 됨

### DrawIndexed

Vertex Buffer와 Index Buffer를 GPU에 준비해두었다면
그 다음 CPU가 GPU에게

> Index Buffer에 적힌 번호를 따라서 정점을 가져와서 그려라

라고 명령하는게 DrawIndexed()다.

## Shadow Mapping

빛의 시점에서 장면을 한 번 찍어보고, 빛이 볼 수 없는 곳은 그림자로 처리하는 방식

```
빛
 ↓
상자
 ↓
바닥
```

빛 입장에서 각 방향마다 가장 먼저 만나는 물체까지의 거리를 저장해둠
이게 보통 Shadow Map이라는 Depth Texture
Shadow Map에는 대략

```
이 방향에서는
빛 → 상자까지 거리 = 5
```

이런정보들이 들어있다. 실제 카메라로 화면을 그릴때 어떤 바닥점을 계산한다고 해보자
GPU가 '이 바닥점은 빛에서 얼마나 떨어져 있지?'를 물었을때 만약 그 점이 빛에서 10만큼 떨어져 있는데
Shadow Map에는 그 방향에서 5만큼 떨어진 곳에 이미 상자가 있다고 적혀 있다면

```
빛
 ↓
상자   ← 거리 5
 ↓
바닥   ← 거리 10
```

빛은 상자에 막혀서 바닥까지 못옴
그래서 이 바닥 픽셀은 그림자 라고 판단한다.
